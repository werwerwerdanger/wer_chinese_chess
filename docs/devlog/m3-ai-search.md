### search.ts v1
- 迭代加深（时间软限 3s，节点间检查 deadline）+ negamax αβ
- 置换表：Map<bigint, {depth,score,flag,bestMove}>，EXACT/LOWER/UPPER 三态，容量 2^18 满了逐半驱逐
- 将军延伸（depth<3 时被将军 +1）；历史启发（beta 截断时 depth² 加分）
- 静态搜索 quiescence：叶子只延伸吃子（MVV-LVA 排序），stand-pat 截断，防水平线效应
- 将杀分数带深度（MATE_SCORE - depth）：快杀优先

### 踩坑（>>报告素材）
**FEN 行号第三次犯错**：测试期望炮吃 (5,4) 的车，实际车在 (4,4)——`4k4/9/9/9/4r4/...` 中 `4r4` 是 row 4。
一度怀疑 movegen 炮逻辑有 bug（输出里 (7,4)→(4,4) "吃子" 且缺 (5,4)），写三个诊断测试逐层查：
局面实际状态 → 发现 (5,4)=255 空格、车在 (4,4) → **引擎是对的，(7,4)→(4,4) 正是隔兵吃车**。
教训：**怀疑引擎前先打印局面实际内容**。FEN 行号从上往下数（row 0 在顶部），"第 N 行"容易和直觉错位；
以后涉及具体格子的测试，直接用 sq(row,col) 常量拼局面而不是手写 FEN。
