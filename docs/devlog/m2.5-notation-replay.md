### 记谱规则实现要点（>>报告素材："数据结构"章节）
- 红方纵线：col 8 = 一线 … col 0 = 九线（中文数字，从红方右手数）
- 黑方纵线：col 8 = 1线 … col 0 = 9线（阿拉伯数字，从**黑方**右手数 = 画面右侧）
- 动作：平（横移）/进/退（纵向，红向上为进、黑向下为进）
- 纵向多格：红"车一进二"（中文数字步数）、黑"车1进2"
- 斜走子（马象仕）：进/退 + 目标纵线
- 同列同名子消歧：前/后缀（红方 row 小者为前，黑方相反）
- 未过河兵不消歧（同列双未过河兵不可能同时有攻击选择）

### 踩坑记录
**坑1：黑方纵线方向想当然**
- 现象：测试期望"卒3进1"，引擎输出"卒7进1"
- 根因：我把黑方纵线当成"从画面左侧数"（col 0=1线），但黑方坐对面，它的右手是画面右侧（col 8=1线）
- 修复：BLACK_NUMS 数组倒序
- 教训：**视角转换类逻辑必须以"该方的视角"写注释和测试**，画个小图确认

**坑2：测试 FEN 构造将帅照面**
- 现象："车一进二"测试找不到走子（no move）
- 根因：构造的 FEN 里红帅黑将同列且中间无子——这局面本身就非法，所有走子被"照面过滤"干掉了
- 修复：两将错开列
- 教训：手工构造测试局面时，先检查局面自身的合法性（照面/被将军），否则测的不是你以为的东西

**坑3：棋子名用繁体**
- 现象：记谱输出"傌八进七"，标准是"马八进七"
- 根因：PIECE_NAMES 沿用了"红方专用字"（傌俥相仕兵）图好看，但标准记谱红黑同用简体（马车炮）
- 修复：统一简体，红黑只靠颜色区分

## 2026-09-12 21:55 PNG 素材接入 renderer（M2.5 收尾）

- drawPiece 双路径：素材就绪 → drawImage（cell*0.92）；未就绪/单张失败 → Canvas 手绘兜底（优雅降级）

## 2026-09-12 22:00 修复 PNG 素材在预览面板不加载的问题

### 现象
用户反馈"棋盘没加载完"——页面空白或棋子全是手绘兜底，PNG 一张没加载（performance API 里 0 个 pieces 请求）。

### 诊断过程（>>报告素材："运行调试"章节）
1. 服务端排查：vite 无报错，所有模块 200，`curl -I /pieces/red_king.png` 返回 image/png ✓
2. 无头浏览器（agent-browser）复现：canvas 600x600 存在、引擎加载成功（status 有值），**但 0 个 pieces 请求** —— 排除 JS 崩溃，锁定资源路径问题
3. 浏览器内手动 `new Image().src='http://127.0.0.1:5173/pieces/...'` → IMG OK；相对路径 `/pieces/...` → FAIL
4. 根因：**预览面板是代理/内嵌加载**，页面不在 vite origin 上下文里，`/pieces/` 这种 origin 相对路径解析到了宿主域名 → 404/失败

### 修复
`img.src` 从 `/pieces/${file}.png` 改为 `new URL('../public/pieces/${file}.png', import.meta.url).href`
- `import.meta.url` 基于模块自身 URL 解析 → 带完整 origin 的绝对地址
- 兼容 dev / 生产构建 / iframe 内嵌预览三种场景

### 验证
无头浏览器重启会话后：28 个 pieces 请求（14张×HMR重复），全部 200，status 正常"轮到红方走棋"。

### 工具坑（记入个人方法论）
- agent-browser daemon 会话会漂移（eval 莫名跑到 about:blank 的新上下文），遇到诡异结果先 `close` 重开
- curl 检查图片资源用 `-I`（HEAD），`-o /dev/null` 在沙箱可能误报 000
